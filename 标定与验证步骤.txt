================================================================
     机器狗 地图坐标标定 与 验证 操作步骤（v3）
     （朝向角 0=正东 顺时针 / simulator 地图界面 / 含 yaw 稳定化）
================================================================

v3 相对 v2 的变更
----------------------------------------------------------------
1. 坐标系变换去掉 90° 偏置（odom 与 IMU 同轴）：参考点处朝向角
   现在确实是 0°（正东），不再是 270°。
2. 新增 [Pose] yaw 稳定化：跳变抑制、静止锁（零偏估计仅用于诊断）。
3. 新增 mapcheck 直线标定预检（只算不改）。
4. mapline 改为分档：≤15° 精确标定、15~40° 粗标定、>40° 拒绝。
5. 标定尺度持久化到 mapcalib_<id>.ini，重建参考后仍保留。
6. 修正本手册中地图尺寸写反的问题（x=宽14，y=高23）。
7. 新增文档末节"常见告警日志对照"。


坐标系约定
----------------------------------------------------------------
局部坐标（狗 MCU 原始输出）
    +x = 机头前方，+y = 机体左侧，yaw 逆时针为正
    注意：odom 位移方位角 = IMU yaw（同轴，已由真狗数据验证），
          因此变换中不再含额外的 90° 偏置。

地图坐标（显示与任务统一使用）
    +x = 正东（屏幕右），+y = 正南（屏幕下）
    朝向角 0=正东，顺时针为正，范围 0~360
    0°=东  90°=南  180°=西  270°=北
    即：东=(+x,0) 南=(0,+y) 西=(-x,0) 北=(0,-y)

参考基准
    参考与狗开机时刻无关：
    - 狗可以先开机，也可以先被遥控移动
    - 终端程序启动后收到的【第一个有效位姿】即参考：
        该位置 = 地图 (0,0)，该朝向 = 0°（正东）
    - 运行中可随时重建参考：
        simulator 命令  mapreset <id>
        或地图界面按钮  [设为原点(0,0 朝向0°)]
    所以：不需要赶在狗开机那一刻启动终端，随时可以补摆、补启。


================================================================
一、准备工作
================================================================

1. 检查终端配置 config/dogterminal.ini
   [Map]
   Enabled=true             启用地图坐标（显示与任务都用地图坐标）
   OriginX=0                摆放点对应的地图 x（摆放点=(0,0) 时保持 0）
   OriginY=0                摆放点对应的地图 y
   AutoReference=true       终端启动后首个有效位姿自动建参考
   JumpCompensate=false     里程计跳变平移参考（会让遥控接管的真实位移在地图上看不到，
                            默认关闭；仅排查坐标系重置问题时临时开启）
   MaxHeadingErrDeg=15      直线标定精确档门限（度）
   CoarseHeadingErrDeg=40   直线标定粗标定上限（度）

   [Pose]  ← v3 新增
   YawStabilize=true        yaw 稳定化总开关（跳变抑制+静止锁；零偏只打印不参与运算）
   StaticLockSec=2          静止多少秒后冻结朝向（0=不冻结；运动/转向时自动解锁）
   YawJumpDeg=15            单帧 yaw 跳变判定阈值（度）

   [Dog]
   HeartbeatRole=remote     心跳不以 sdk 身份抢占控制权
   AutoAcquireControl=true  连接后自动申请SDK控制权；设为 false 时由服务端下发
                            control <id>（姿态命令 10=申请控制权）手动触发
   AcquireRetryCount=1      申请控制权的重试次数（0=只申请一次）
   PrintStateHz=1           控制台 1Hz 打印（建议改 2~5，便于排查跳变）

2. 检查 simulator 配置 config/simulator.ini
   [MapUI]
   WidthM=14                地图宽度（x 方向，东西向，米）
   HeightM=23               地图高度（y 方向，南北向，米）
   → 坐标范围 x∈[-7, +7]、y∈[-11.5, +11.5]，(0,0) 在正中心

3. 重新编译（协议与配置都有改动，两端必须一起重编）
   终端:      删除旧 .o 后重新 qmake && make
   simulator: qmake && make    （Qt Widgets 界面）

   启动后终端第一屏应出现构建标识：
   [Main] 构建标识: MAP-XFORM=V2(odom同轴) 局部坐标=相对参考位移
                    YAW-STAB=1 标定分档=精确/粗+mapcheck
   若看不到这一行或内容不同 → 跑的还是旧程序，必须重新编译。

4. 启动顺序（任选，不要求同时）：
   1) 狗上电
   2) 启动终端程序
   3) 启动 simulator（默认弹出地图窗口；--nogui 可关闭）


================================================================
二、地图显示界面（simulator）
================================================================

界面元素：
   - 白色区域：地图，宽(x)14m x 高(y)23m，(0,0) 在地图正中心，
     向右=东，向下=南，每 1m 细网格、每 5m 粗网格 + 米数刻度
   - 橙色箭头：狗位置与朝向（地图坐标，箭头指向 = 朝向角，0° 指向右=正东）
   - 绿色箭头（虚线轨迹）：狗【局部坐标（相对参考点位移）】叠加显示，
     仅已标定时绘制，起点与地图 (0,0) 重合，与橙色地图图标/蓝色轨迹
     同框对比，用于观察坐标系偏差（注意：局部 +y=左 与地图 +y=南 手性
     相反，转弯时绿/蓝轨迹呈镜像属正常现象）
   - 右上角罗盘：灰箭头=地图系（固定 东/南），绿箭头=局部系 +x 轴方向
   - 顶部文字：地图坐标 / 局部坐标 / 数值差(dx,dy) / 局部系+x轴的地图角 /
     机体系速度 / 电量
   - 底部三行：
       [终端选择] [设为原点] [清除轨迹]
       [mapcheck (2,0)] [mapline (2,0)] [取得控制权]  W=前进 S=后退
         三个快捷键作用于“显示终端”下拉框当前选中的终端，与下列命令等价：
           mapcheck 1 2 0 / mapline 1 2 0 / control 1
         W/S 为机体系速度直控（默认 0.3m/s）：按住持续前进/后退，每 100ms
         续发一次；松开、同时按 W+S 或地图失焦立即零速。需先点击地图获取
         键盘焦点（命令框有焦点时 W/S 会作为文字输入）。
       [命令输入框 + 发送按钮]  —— 与控制台命令相同，回车即下发
         例如: fwd 1 1 / rotate 1 90 / mapcheck 1 2 0 / mapline 1 2 0 / help
         下发结果（日志/错误提示）显示在运行控制台窗口

图标颜色含义：
   橙色 = 已标定（地图坐标生效）    蓝色实线轨迹 = 地图坐标轨迹
   绿色 = 局部坐标叠加（对比用）    绿色虚线轨迹 = 局部坐标轨迹
   黄色 = 未标定（终端未启用地图或未建参考，显示的是局部坐标）
   红色 + 红圈 = 位置超出地图范围（钳制在边缘显示）

叠加对比读法：
   - 数值差 dx/dy：地图位置与局部（相对参考）位置的残差。两套坐标以
     同一参考点为原点，理想情况 dx/dy≈0，偏差=变换误差+里程计漂移。
   - 局部系+x轴 地图角：局部坐标系相对地图系的旋转差。
     【判据是"保持不变"，数值本身没有固定含义】——该值等于 mapreset
     那一刻的原始 IMU yaw（IMU 零点随开机任意），所以可能是 183°、
     330° 等任意值。只要狗转动时它保持恒定，就说明两坐标系无相对旋转。
   - 标定成功后两箭头位置应基本重合；该角度整体改变 = 参考朝向被修正。


================================================================
三、基础标定（三步，免开机时机限制）
================================================================

步骤 1  摆放
        把狗摆在场地中的固定点 P（P 就是地图 (0,0)）。
        何时上电无所谓——狗可以先开机放着，也可以先遥控走动。

步骤 2  启动终端
        终端程序启动后，收到第一个有效位姿时自动打印：
        [Map] 参考已建立（终端启动时狗位姿=O点/0°正东）: 参考局部(...) 原点(0.00, 0.00) refYaw=..° scale=1.000
        此刻：狗位置 = 地图 (0,0)，狗朝向 = 0°（正东，界面箭头指向右）。

步骤 3  随时校正（可选但推荐）
        如果启动终端后狗又被挪动过，把狗摆回 P 点、摆正朝向后，
        点界面 [设为原点] 按钮（或 simulator 执行 mapreset 1），
        日志打印 [Map] 参考已重建（当前点=O点 朝向=0°正东）。

判定：
   - 界面狗图标位于地图正中心 (0,0)、箭头指向右（东）
   - 顶部文字 地图: x=0.00m y=0.00m 朝向=0.0°
   - 若朝向不是 0°：确认是否跑的是旧二进制（看第一步的构建标识）


================================================================
四、验证场景：从地图中心出发再回到中心
================================================================

前提：完成第三节标定。(0,0) 就是地图正中心，即摆放点 P 本身。

步骤 1  遥控把狗从中心开出去，绕一小段（如 3~5m）再回到 P 点附近停稳
步骤 2  把狗头调回正东（朝向角 ≈ 0°）
步骤 3  读界面 / 终端日志：

预期结果：
   界面:  地图: x=0.0m  y=0.0m  朝向=0.0°（箭头指向右）
   日志:  [DogState] ... 地图(x 0.00, y 0.00, yaw 0.0°, scale 1.000)

也可以在界面命令框直接下发（让狗自己走回中心）：
   move 1 0 0
   预期：狗走到中心，终点偏差 ≤ 0.2m（软到达半径内）。

判定（未做直线标定时允许的误差）：
   - 回中心位置偏差 ≤ 0.5m（里程计本身有漂移）
   - 朝向 ≤ ±5°
   若朝向偏差大：检查是否有 [Pose] 静止锁生效（静止 5s 后朝向应冻结），
   未开静止锁时属静止漂移累积（约 0.2~0.4°/s）。
   若位置偏差方向一致、随行走距离增大 → 属里程计尺度误差，
   用第五节直线标定修正。


================================================================
五、直线标定（推荐：先预检，再正式标定）
================================================================

作用：修正两件事 —— ① 参考朝向（refYaw）残余误差 ② 里程计尺度（scale）

步骤 1  从 P(0,0) 出发，用遥控器开环沿【正东】直线走到地面标记点 B
        （例如正东 2m，B 的地图坐标 = (2, 0)），停稳。

步骤 2  预检（只计算不修改，可反复试）：
           mapcheck 1 2 0
        日志返回当前位移、尺度、残余朝向，例如：
           [Map] 标定预检: 预检通过(精确档)：位移 2.00m，尺度 1.000，残余朝向 3.21°
        若提示失败，按提示调整后重走，不会污染已有参数。

步骤 3  正式标定：
           mapline 1 2 0
        格式：mapline <终端ID> <终点地图x> <终点地图y>
        （协议 0x19，action=3 为 mapcheck，action=1 为 mapline）

分档规则：
   残余朝向 ≤ 15°（MaxHeadingErrDeg）
         → 精确标定：同时修正参考朝向与尺度
         → 尺度写入 mapcalib_<id>.ini，以后重建参考仍保留
   残余朝向 15° ~ 40°（CoarseHeadingErrDeg）
         → 粗标定：只修正参考朝向，尺度固定为 1
         → 说明这条线走得不够直，建议重走一次
   残余朝向 > 40°
         → 拒绝，参数不变

预期日志（成功）：
   [Map] 直线标定成功: 精确标定完成：位移 2.00m，尺度 1.000，残余朝向 3.21°
   [Map] 当前参数: ...

失败处理（日志会给出具体原因，参数不会被改动）：
   - "局部位移仅 x.xxm，小于门限 1.00m" → 走得太短，加长重走
   - "尺度 x.xxx 超出允许范围" → 狗没从 P 出发或中途被抱起，重走
   - "残余朝向误差 xx° 超出上限 ±40°" → 方向偏差过大，确认是从 P 点
     沿直线走出、狗未中途打滑
   - "任务执行中" → 等狗停稳、无任务时再标
   - "里程计尚未就绪 / 地图坐标未启用或参考未建立" → 先完成第三节

注意：
   - 必须用遥控器开环走，禁止用终端 move 闭环走（否则标定无意义）
   - 重复标定以最后一次为准
   - 大场地建议标定更长的线（≥3m），尺度估计更稳


================================================================
六、yaw 稳定化与跳变处理（v3 新增）
================================================================

背景：狗端存在两类朝向问题
   a) 静止时 IMU yaw 缓慢漂移 0.2~0.4°/s
   b) 遥控接管、模式切换时 odom/IMU 基准可能整体重置
      （历史日志出现单帧 4.00m、6.91m 的位置跳变）

终端的三层处理（[Pose] 段）：
   1) 跳变抑制  单帧 yaw 变化超过 max(15°, 8·|gyro_z|·dt) 时，
                判定为基准重置，忽略该帧，朝向保持连续
   2) 零偏估计  静止时用 gyro_z 低通跟踪，仅用于日志打印和静止锁判断，
                不再从 yaw 增量中扣除（扣除会吃掉慢速转向，并反向引入漂移）
   3) 静止锁    静止（无导航/速度直控，且 |vBody|<0.02、|gyro_z|<0.05rad/s）
                超过 StaticLockSec（默认 2s）后冻结朝向，漂移不再累计；
                开始运动/转向会立即自动解锁

正常日志（静止 2s 后）：
   [Pose] 静止 2.0s，yaw 已锁定（零偏≈0.285°/s），漂移不再累计
   [DogState] ... 稳定yaw=0.32° 零偏=0.285°/s [静止锁定]

发生基准重置时：
   [Pose] 检测到 yaw 跳变 87.3°，已忽略并保持连续朝向 0.5°
   （位置跳变由 [Map] 里程计跳变 的处理平移参考，地图不会跳飞）

说明：
   - 静止锁期间若用手缓慢转动狗（<2.9°/s）朝向不会更新，属设计取舍；
     需要精确朝向时遥控正常速度转一下即可解除锁定。
   - 若发现"转向时朝向不跟随"，先确认 YawJumpDeg 是否被改得过小（默认 15）。


================================================================
七、验证清单（全部通过再投入任务）
================================================================

【A】朝向换算
   mapreset 后狗头朝东（0°），simulator 执行：rotateTo 1 90
   预期：狗顺时针转 90°，狗头朝南，界面朝向角 90°（箭头向下）
   再执行 rotateTo 1 180 → 朝西；rotateTo 1 270 → 朝北；
   rotateTo 1 0 → 回正东。到位误差 ≤ 5°。

【B】相对移动方向
   狗头朝东停稳，simulator 执行：fwd 1 1
   预期：狗向东前进 1m，界面 x 增加 1、y 基本不变。
   再执行：side 1 1
   预期：狗向左（朝东时左侧=北）平移 1m，界面 y 减少 1（向北）。

【C】地图坐标任务
   狗在地图中心朝东，simulator 执行：move 1 3 2
   预期：狗走到 东3m、南2m 的位置，终点偏差 ≤ 0.3m。
   （注意地图范围 x∈[-7,7]、y∈[-11.5,11.5]，超出会被钳制显示）

【D】轨迹闭环
   遥控狗绕一小圈回到出发点：
   预期：轨迹曲线闭合，回到起点位置偏差 ≤ 0.3m（短圈）。
   （长时间/大圈/大量原地旋转会放大里程计漂移，见注意事项）

【E】状态字段
   simulator 控制台位姿行 calib=1，且与界面数字一致；
   界面"数值差 dx/dy"在参考点处应 ≈ 0。

【F】禁止倒退
   狗在中心朝东，下发一个位于侧后方的目标（如 move 1 -1 1）：
   预期：狗先原地转向对准目标，再前进；不会倒着走过去。


================================================================
八、注意事项
================================================================

1. 参考以"终端启动那一刻"或"最后一次 设为原点/mapreset"为准；
   狗重新上电后里程计归零，需重建参考（AutoReference=true 时，
   参考丢失后首个有效位姿会自动补建）。
2. 狗静止时朝向角会缓慢漂移（约 0.2~0.4°/s），[Pose] 静止锁可抑制；
   转向/行走时 yaw 本身是准确的，不要据此频繁重建参考。
3. 遥控走位避免原地满杆猛转（打滑会让里程计产生米级跳变）；
   需要转向时优先用 rotate / rotateTo 命令。
4. 导航任务默认【禁止倒退】（Nav AllowBackward=false）：目标在侧后方时
   狗先转向对准再前进，不会倒着走；如需恢复倒车接近改为 true。
5. 长时间任务建议：出发前 设为原点 + mapline 直线标定一次，
   回到已知点后再校正一次。
6. 摆放点放在地图中心附近，留出活动空间；位置超出
   x∈[-7,7]、y∈[-11.5,11.5] 范围时图标会钳制在边缘（红圈提示），
   此时应扩大 [MapUI] WidthM/HeightM。
7. 每次启动先核对构建标识行，避免"改了代码但跑的是旧程序"。


================================================================
九、常见告警日志对照
================================================================

[Main] 构建标识: MAP-XFORM=V2 ...
      正常。确认含 YAW-STAB=1；没有这行说明是旧程序。

[Map] 参考已建立 / 参考已重建
      正常。表示地图原点与朝向基准已确定。

[Map] 里程计跳变 4.00m (dt=100ms, vBody=0.00m/s)，已平移地图参考保持连续: ...
      狗端 odom 坐标系被重置（通常是遥控器接管瞬间）。
      终端已补偿，地图保持连续；若频繁出现，优先改用时钟直连或
      降低遥控接管频率，并向厂商确认 odom 重置策略。

[Pose] 检测到 yaw 跳变 xx.x°，已忽略
      同上，IMU 基准被重置。已忽略该帧，朝向保持连续。

[Pose] 静止 x.xs，yaw 已锁定
      正常，静止漂移已被冻结。

[Map] 直线标定被拒绝: ...
      按提示修正后重试；先用 mapcheck 预检确认能否通过。

[Map] 直线标定失败: 残余朝向误差 xx° 超出上限 ±40.0°
      走线不直或起点不对。确认从 P 点直线走出，长度 ≥1m（建议 ≥3m）。
